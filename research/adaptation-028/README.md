# ADAPTATION 028 — dynamic preservation
Research simulation only. Python 3.10+, standard library. From this directory run PYTHONPATH=../interdependence-026 python adaptation.py (POSIX). Six peers, three paired failure domains, 48 ticks, 24 initial objects with six fixed XOR relationships, new objects every six ticks. Actual ID1 decoder assesses availability; repair copies and parity-derived repairs are hash-verified. No new parity generation, parity repair or live deletion. 6,500 B per tick, 32,000 B per repair destination admission ceiling; exogenous ingress excluded. Costs model encoded payload plus 32 B address; regeneration pays input plus output transfers. Initial placement, new arrivals, inventories, transport overhead and parity metadata excluded. Four policies: static four-tick admission window, reactive two online copies, durable two advertised domains, adaptive four-tick stale-inventory discount and observed wipes. Synthetic outages and wipes; matched event traces, no future access by policies.

Main: 96 runs (8 seeds per regime, four policies). Permanent losses in attrition: static 193, reactive 48, durable 131, adaptive 84. Modeled transfer bytes respectively 366174, 1638918, 999057, 1316619. Reactive wins availability and permanent-loss metric at higher expenditure.

Fresh lifetime-cap follow-up: 144 runs, six new seeds per regime, 100000/160000 B ceilings. At 100000 B, permanent losses in attrition: static 175, reactive 161, durable 159, adaptive 136; correlated: static 141, reactive 118, durable 98, adaptive 124. Reactive still has fewer missing object-ticks in correlated cases. At 160000 B reactive has lowest missing object-ticks and permanent losses (ties transient zero). No universal winner.

Retirement follow-up: 36 runs, new seeds, reactive with/without retirement, 160000 B cap. Retire simulated direct copies only on online peers at >=75% capacity if two live domains remain. Default disabled. Transient aggregate final storage falls from 1187904 to 827286 B, repair transfer rises from 791091 to 958614 B, missing object-ticks rise from 316 to 463. Both zero permanent losses. No real deletes.

Total 276 runs, 13248 ticks, 23568 verified repairs (459 parity-derived). Separate 36 local filesystem recovery attempts matched every model missing set, six complete restores, 24 regenerated objects. Six tests passed normal and optimized Python. Synthetic data, not real operational peers. Follow-ups selected post hoc; no learned hazard probabilities, production audit, real networking or remote CI. Missing object-ticks count unavailable objects after repair; permanent loss means no recovery even from all surviving stores including offline. Main benchmark's static comparator is not a production backup system.
